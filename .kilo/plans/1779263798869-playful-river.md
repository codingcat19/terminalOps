# Project Understanding: TerminalOps

## Overview
TerminalOps is a terminal-first DevOps agent built with Strands and Ollama. It provides an interactive CLI interface for common DevOps tasks with built-in safety checks for state-changing operations.

## Key Components

### CLI Interface (`terminalops/cli.py`)
- Interactive REPL with commands: `/help`, `/tools`, `/clear`, `/status`, `/exit`
- Direct handling of common queries:
  - System resources (CPU, RAM, disk) via `check system resources`
  - System time via time/date keywords
  - Git status via `git status` or `current branch`
  - Docker containers via `docker ps` or `running containers`
  - Follow-up queries like "Please show it" or "show me" repeat last resource check
- Safety layer requiring approval for state-changing shell commands
- Session management with `/clear` to reset agent memory

### Agent Construction (`terminalops/agent.py`)
- Creates Strands agent with Ollama model
- Uses configuration from `terminalops.config`:
  - Default agent name, model host, model ID
  - System prompt
- Handles missing dependencies with `MissingDependencyError`

### Tools (`terminalops/tools.py`)
- Shell command execution with approval system
- Docker operations: list containers, get logs, run/stop containers
- Git status reporting
- System time reporting
- System resource monitoring (CPU, RAM, disk usage via psutil)
- Safety integration via `needs_confirmation()` from `terminalops.safety`

### Configuration
- Python 3.10+ required (Strands compatibility)
- Dependencies in `requirements.txt`
- Entry point via `bin/terminalops` and `setup.py`
- Virtual environment setup documented in README

### Testing (`tests/test_cli.py`)
- Unit tests for CLI command handling
- Tests for agent recreation on `/clear`
- Direct prompt handling verification
- Dependency error handling
- Mock-based testing approach

## Interaction Flow
1. User starts `terminalops` CLI
2. Sees banner with model info
3. Enters commands at `>` prompt
4. CLI processes input:
   - Special commands (`/help`, `/tools`, etc.) handled directly
   - Direct requests (resources, time, git, docker) handled via built-in functions
   - Other prompts passed to Strands agent with available tools
5. For shell commands: safety check determines if confirmation needed
6. Agent executes approved commands and returns results
7. Session can be cleared with `/clear` to reset agent memory
